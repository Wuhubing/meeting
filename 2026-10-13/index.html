Three levers on cost

Total cost ≈ K policies × N iterations × cost per iteration

#What to optimizeQuestionHow
1Cost per iteration
the simulation itself		Can one simulation run faster?
  • Compute indicators online instead of writing event files every iteration
  • Move heavy event handlers (scoring, travel-time stats) off the single events thread
  • Precompute time-varying link capacities per period instead of looking them up each step
  • Keep only changes with bit-identical results; make them the default config
2N
iterations per policy		Can one policy reach the same end state in fewer iterations?
  • Log every agent's replanning and label whose innovation actually changed the outcome
  • Measure the ceiling first: a hindsight oracle that only lets those agents innovate
  • Train a classifier (score gap, recent changes, congestion exposure) to predict them
  • Give the innovation budget to predicted agents, plus a small random share
3K
number of policies		Can a policy study skip runs, or stop recomputing from scratch?
  • Run a few charge levels cold as anchors
  • Warm-start the others from the nearest solved policy; replan only affected agents; shorter runs
  • Fit the response across charge levels; add runs only where it bends (near zero)
  • Stop when interpolated results fall within seed noise (2σ)

1 is engineering and becomes the baseline for every experiment. 2 and 3 are research: pick one as the main contribution by Nov 17, from the RQ2 ceiling and the Berlin check.

Reading group: POLARIS vs. MATSim

POLARIS lives the day once: decisions are made in the moment, reading current traffic (within-day). MATSim replays the same day many times: execute, score, replan, repeat (day-to-day). Note where each feedback loop sits.

POLARIS C++ · shared-memory threads · SQLite

MATSim Java · open source · XML

Solid colored arrows = main feedback loop. POLARIS feeds network state straight back into demand within the day; MATSim feeds back between iterations, via scoring and replanning. Dashed = secondary loop. Adapted from our reading-group notes (Auld et al. 2016; MATSim user guide).

Candidate generic problems

  1. Stopping is set by protocol, not by a convergence test.
  2. Most innovation is wasted. Can we predict who needs to replan? (L2Seg analogue)
  3. Every policy is recomputed from scratch, though most agents are unaffected.
